Включены supervise-daemon, ограничение повторных запусков и автозапуск в default. Production-контейнеры ботов не запускаются; собранные образы использовались для изолированных тестов.

- Поиск секретов в публикуемом дереве не нашёл настоящих Telegram-токенов или приватных ключей; совпадения в тестах — фиктивные данные. Реальные `.env`, базы и журналы исключены из Git. Истории коммитов пока нет.

- Успешно выполнены start/status/restart. Сохранены файлы SQLite ChatBot/BotWork; после рестарта ChatBot прошёл проверку схемы базы. Файл состояния ServerBot существует после рестарта и обновляется атомарно.
- `.env` имеет root:botwork, 0640; процесс читает свой секрет, не может его изменять и не может читать `.env` других ботов. Код и venv принадлежат root. Запись разрешена только в выделенное состояние и журналы.

## Эксплуатация

От root на Alpine:

```sh
rc-service botwork status
rc-service botwork restart
rc-service botwork stop
rc-service botwork start
```

Секреты: `/srv/bots/botwork/.env`. После их изменения нужен restart. Журналы: `/var/log/botwork/`; logrotate — daily/maxsize 10M, три архивных файла, copytruncate. Исходные env перед настройкой прокси сохранены root-only в `/root/bots-env-before-start-20261105/`.

Откат первого развёртывания: остановить службу и исключить её из default (`rc-update del botwork default`), сохранив код, секреты и данные. Удалять базы для отката не требуется. После будущих миграций нужен совместимый backup базы.
