# WorkBot

Вакансии и события по ключевым словам. Один владелец, автоматическая проверка, короткие карточки и история отправок в приватной SQLite-базе.

```sh
cp .env.example .env
uv sync --locked
uv run bot
```

Заполните BOT_TOKEN и OWNER_ID в .env. Источники и исходные слова задаются в config.toml. Изменения слов из Telegram сохраняются в базе после перезапуска.

- /jobs [слово] — последние пять вакансий.
- /events [слово] — пять ближайших событий.
- /keywords — слова; /keywords SOC, DevOps, CTF — заменить.
- /exclude слово, фраза — исключения; /exclude - — очистить.
- /check — обновить источники в фоне.
- /status — результаты и ошибки; /help — справка.

Совпадение хотя бы одного слова/фразы в названии, категориях или описании. Исключения имеют приоритет. Регистр и ё/е не важны; длинные слова можно задавать частью слова, короткие сокращения проверяются целиком. Ограничений по городу и стажу нет. Закрытые наборы и завершённые события не отправляются. Неизвестная регистрация явно помечается.

Ошибка источника сохраняет предыдущий снимок и приостанавливает его рассылку до успешной проверки. Отправленное объявление не рассылается повторно при смене статуса набора. Строго совпадающие объявления разных источников объединяются по метаданным. Сбой между успешной отправкой Telegram и фиксацией SQLite может повторить одно сообщение.

Тесты: `uv run pytest`. Проверка без Telegram и записи в базу: `uv run bot preview`. Пример без сети: `uv run bot demo`. Для работающей службы используйте /status: локальные команды используют блокировку экземпляра.

[Парсеры](docs/parsers.md) · [Команды](docs/telegram-interface.md) · [Службы](../../../docs/setup-and-operations.md)

Обновление сохраняет объявления, историю доставки и прежние личные заметки. Профили, CRM, закладки, напоминания и прежние меню больше не используются. Перед обновлением остановите службу и сохраните SQLite через backup API. Старые личные данные удаляйте после сохранения защищённого архива.
