# AgentBot

Telegram-клиент OpenCode 2 для одного владельца: задачи, файлы, CTFd-борды, диалог, мониторинг и остановка. Публичный HomeLab содержит интерфейс и контракт транспорта. CTF-harness, инструменты, промпты, приём файлов и клиент борды остаются в закрытом проекте.

## Запуск

Нужны Python 3.12+, uv и непривилегированный пользователь:

```sh
cp .env.example .env
# Заполнить .env локально.
uv sync --locked
uv run bot --check
uv run bot
```

Обязательны `BOT_TOKEN`, положительный `OWNER_ID` и абсолютный `OPENCODE_DIRECTORY` на машине агента. Доступ разрешён только владельцу в личном чате. `OPENCODE_AGENT` выбирает существующего агента; модель, инструменты и ограничения определяет OpenCode. Опциональный `PROXY_URL` используется только для Telegram. CLI отказывается работать от root. `--check` проверяет конфигурацию и доступность состояния без сетевых запросов.

## Подключение

Выберите один транспорт:

- HTTP: `OPENCODE_URL` и `OPENCODE_SERVER_PASSWORD`; Basic Auth с именем `opencode`. HTTP разрешён через loopback, удалённый адрес требует HTTPS. Редиректы запрещены.
- `OPENCODE_COMMAND`: доверенная команда с фиксированными аргументами, например SSH-helper. Пароль API боту не требуется. Аргументы разбираются через `shlex`, shell не запускается. Текст задачи передаётся через stdin.

Команда получает JSON-запрос:

```json
{"method":"GET","path":"/api/session/active","body":null,"params":null}
```

Ответ — `{"ok":true,"data":<ответ API>}` либо `{"ok":false,"error":"unavailable"}`; для HTTP 204 значение `data` равно `null`. Stdout содержит только JSON, stderr отбрасывается. Вызов ограничен 20 секундами, ответ — 16 МиБ. Helper, ограничения разрешённых операций и доступ к паролю реализуются в закрытом harness. Отдельной очереди или демона транспорт не требует.

## Работа и восстановление

Постоянная клавиатура: «Задача», «Борда», «Мои задачи», «Статус», «Остановить», «Помощь». Карточки показывают короткий номер и название (`#3 · Weird RSA`), скрывая внутренний ID. Кнопки уведомлений относятся к указанной задаче, даже если выбрана другая. Название можно изменить. Списки разбиты на страницы.

«Задача»: отправьте название и условие одним сообщением, добавьте документы/фото, нажмите «Начать». Первая строка становится названием. Файлы до 8 МиБ передаются на машину агента как данные, без распаковки или исполнения; до 32 файлов на задачу. Для форензики отправляйте изображения документом, чтобы Telegram не сжал их.

«Борда»: адрес CTFd, режим доступа (логин/пароль, API-токен или без входа), разрешённые задачи и выбор отправки флагов. Запуск — отдельной кнопкой после карточки. Без явного разрешения флаги не отправляются. Пароль/токен передаётся закрытому адаптеру отдельно от задания; после подтверждения сохранения бот пытается удалить входящее сообщение. Секрет не сохраняется в SQLite бота, не включается в промпт или карточку. При ошибке сохранения шаг остаётся активным, а сообщение не удаляется.

Черновики, шаги ввода и номера сохраняются в SQLite, включая после перезапуска. Доступ хранится отдельно на машине агента. Файлы и борды требуют закрытого транспорта с POST `/agentbot/session/<id>/intake`, `/file`, `/access`; обычный HTTP OpenCode поддерживает текстовый сценарий.

Команды видны в меню Telegram: `/new`, `/board`, `/sessions`, `/status`, `/result`, `/stop`, `/help`, `/cancel`; `/use <номер>` тоже работает. В списке только созданные этим ботом сессии. Обычный текст продолжает выбранную задачу после её ответа. В одной сессии допускается одна незавершённая работа. Запросы разрешений OpenCode бот автоматически не подтверждает.

Задача сохраняется до отправки. Принятый запрос выполняется существующим OpenCode независимо от соединения бота. Монитор проверяет статус каждые `POLL_SECONDS`, прогресс отправляется примерно раз в минуту. При неоднозначной отправке автоматического повтора нет: проверьте сессию или остановите её перед новой попыткой. `/stop` сохраняет запрос, отменяет собственный ожидающий ввод и прерывает выполнение после восстановления связи.

Приватное состояние и ответы хранятся в `STATE_FILE`, по умолчанию `data/agentbot.sqlite3`; каталог исключён из Git. Один процесс использует один файл состояния. После перезапуска доставка продолжается; сбой сразу после отправки может повторить последний фрагмент. Тексты задач, токены, параметры прокси и исходные исключения не журналируются.

`deploy/agentbot.openrc` — шаблон отдельной службы Alpine. В `/etc/conf.d/agentbot` можно задать `uv_path`, `agentbot_user` (user:group), `agentbot_directory` и `agentbot_log_directory`; стандартные значения рассчитаны на отдельного пользователя `agentbot` и `/srv/homelab/apps/bots/agentbot`. Перед обновлением сохраните код, lock-файл и SQLite через backup API либо после остановки AgentBot. Для отката верните сохранённую версию и состояние; другие службы не затрагиваются.

Проверки: `uv run pytest`. Подтверждены запрос через OpenCode 2.2.5, реальный Telegram-диалог с продолжением, доставка после разрыва SSH и перезапуска бота, остановка активной безопасной задачи. Проверки выполнялись отдельно от CTF-замеров.
