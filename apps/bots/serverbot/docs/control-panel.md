# Панель управления ServerBot

Вход: «⚙️ Управление» под `/status` или `/panel`. На главном экране — Kali,
ChatBot, WorkBot и OmniRoute.
ServerBot не управляет собственной службой.

Карточка показывает текущее состояние и подходящие кнопки: запустить,
остановить, перезапустить. Для Kali — включить, выключить, перезагрузить.
Все действия требуют подтверждения, действующего 60 секунд, только для
запросившего пользователя и исходного сообщения. Подтверждение одноразовое;
отмена и переход в другую карточку его аннулируют.

Во время выполнения кнопки убираются. Повторная операция для того же объекта
блокируется и в боте, и системным исполнителем. Успех показывается только после
проверки состояния через OpenRC/libvirt. Неизвестное состояние не считается
остановкой и не предлагает действий.

Выключение Kali штатное, с ожиданием до 90 секунд. Перезагрузка — штатное
выключение и последующее включение с проверкой обоих переходов. Принудительного
отключения нет. Состояние «Работает» подтверждает работу VM, а не готовность SSH
и задач внутри неё. Панель не меняет автозапуск.

## Ошибки

В карточках служб кнопка «Ошибки» показывает до десяти последних предупреждений
и ошибок из доступного хвоста журналов, включая многострочный traceback.
Обычные DEBUG/INFO-записи отбрасываются. Длинные результаты разбиваются по лимиту
Telegram; слишком большая одиночная запись явно помечается как сокращённая.

Боты: фиксированные `/var/log/<бот>/<бот>.log` и `<бот>-error.log`, не более
128 КиБ из каждого файла. OmniRoute: `/usr/bin/podman logs --tail 300 omniroute`
из root-контейнера с таким именем. Отсутствующий журнал показывается как
недоступный. Символические ссылки и специальные файлы не читаются.

Перед отправкой скрываются типичные токены Telegram, Bearer/Basic-авторизация,
пароли, ключи и секреты в именованных полях. Это дополнительная обработка;
приложения также не должны записывать секреты в журналы.

## Установка на Alpine

Панель использует существующий список `ALLOWED_USER_IDS` и только личный чат.
Бот остаётся непривилегированным. Единственное разрешение doas — root-owned
исполнитель с фиксированными объектами и действиями. Он запускает Python
с `-I`, не принимает пути, команды shell, произвольные имена служб и VM.

Из каталога `/srv/homelab/apps/bots/serverbot`, от root:

```sh
apk add doas
install -d -o root -g root -m 755 /usr/local/lib/homelab /var/lib/homelab-control /etc/doas.d
install -o root -g root -m 755 deploy/host/control.py /usr/local/lib/homelab/control.py
install -o root -g root -m 755 deploy/host/probe.py /usr/local/lib/homelab/probe.py
install -o root -g root -m 600 deploy/serverbot.doas.conf /etc/doas.d/serverbot.conf
doas -C /etc/doas.d/serverbot.conf
```

Проверьте чтение от пользователя ServerBot, без изменения состояния служб:

```sh
su -s /bin/sh serverbot -c '/usr/bin/doas -n /usr/local/lib/homelab/control.py list'
```

Затем добавьте в используемый `config.local.toml` (или измените существующую
секцию в конфигурации, выбранной через `SERVERBOT_CONFIG`):

```toml
[control]
enabled = true
```

Обновите код бота по [общей инструкции](../../../../docs/setup-and-operations.md)
и перезапустите службу. В отслеживаемом примере управление выключено, пока
исполнитель не установлен. Для чтения ошибок OmniRoute нужен доступный
root-контейнер `omniroute`; для Kali используется домен `kali-ctf` в
`qemu:///system`. Настройки не содержат адресов и секретов.

Правила каталога `/etc/doas.d` описаны в
[документации Alpine](https://docs.alpinelinux.org/user-handbook/0.1a/Working/post-install.html).
Интерпретация состояния OpenRC опирается на
[реализацию supervise-daemon](https://github.com/OpenRC/openrc/blob/master/sh/supervise-daemon.sh):
код 0 означает запущенную службу, 3 — остановленную; остальные состояния
показываются как неизвестные.

## Мониторинг ручной остановки

Исполнитель записывает результат в root-owned `/var/lib/homelab-control/`.
Сборщик `probe.py` показывает «Остановлен вручную» для объекта и связанных
проверок (процесс, база, SSH или API) только после проверки фактической остановки.
Остальные службы и сеть продолжают проверяться. Намеренная остановка
не создаёт уведомлений о сбое или восстановлении.

Во время операции связанные проверки временно помечаются как выполняемые;
эта отметка истекает через три минуты. Ошибка или таймаут не выдаются за успех.
Ручной запуск через панель снимает отметку остановки; запуск через SSH снимает её
при следующем замере сборщика. После перезагрузки сервера старые отметки не
применяются. Обновление общей сводки зависит от минутного снимка; карточки
управления получают состояние напрямую.

Действия пишутся в служебный журнал ServerBot без текста сообщений и без
сырого вывода системных команд. Отдельных экранов истории и задач нет.
