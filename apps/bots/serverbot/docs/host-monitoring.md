# Мониторинг Alpine и обслуживание пакетов

## Что установлено

ServerBot читает `/var/lib/homelab-health/host.json`. Файл атомарно обновляется root-заданием каждую минуту; бот и остальные пользователи менять его не могут. Сам бот сохраняет прежние непривилегированные права. Источник реализации: `deploy/host/probe.py` и `deploy/host/updates.py`.

Проверки: одиннадцать OpenRC-служб, включая OmniRoute и nginx, локальный health endpoint gateway, отдельный процесс каждого бота, схема базы ChatBot, чтение базы и число ошибок источников BotWork, состояние Kali через системный libvirt, SSH-баннер Kali, DNS и HTTPS до Alpine CDN, chrony, NVMe SMART, inode и swap. Обычные проверки CPU/RAM, свободного диска, температуры и питания остались.

Два неуспешных минутных замера подтверждают проблему; восстановление отражается сразу. ServerBot читает результаты раз в пять минут и уведомляет о смене состояния, сводка приходит в 08:00 по Москве. Snapshot старше трёх минут считается неисправностью сборщика. Все результаты видны через `/status`.

Проверка процесса и базы не доказывает, что каждый Telegram-обработчик отвечает. При полном отключении хоста или его сети отправка уведомления невозможна. Внешний наблюдатель отложен владельцем. Проверки резервных копий не включены.

## Автообновления

`/etc/periodic/daily/homelab-updates` запускает `/usr/local/lib/homelab/updates.py` через существующий daily cron. Результат хранится в `updates.json`, вывод — в `/var/log/homelab-updates.log`. Скрипт:

1. Проверяет, что репозитории относятся к Alpine v3.24, затем обновляет индексы.
2. Считает все доступные обновления, чтобы показать их в ServerBot.
3. Симулирует обновление ограниченного списка: curl/libcurl, nano, libarchive, libexpat, brotli-libs, cups-libs, perl и связанные разрешённые подпакеты.
4. Отказывается применять транзакцию, если она затрагивает другие пакеты или меняет состав системы.
5. Получает старые версии всех затронутых APK в `/var/lib/homelab-health/apk-rollback` для возможного ручного отката. Если старый APK недоступен, откладывает обновление.
6. Применяет разрешённую транзакцию и публикует результат. Автоматической перезагрузки нет.

Ядро, musl, apk-tools, Python, SSH, сеть, firewall и виртуализация требуют отдельного обслуживания. Зависимости Python-проектов и Kali этим заданием не обновляются. Старые APK — материалы для ручного отката пакетов, не резервные копии пользовательских данных.

Первый реальный запуск 05.11.2026: 32 доступных обновления, применено 0 — старые APK отсутствуют в репозитории. Автоприменение настроено, но успешная установка и ручной откат пакетов на сервере не проверены. Защитная ветка отказа проверена тестом. Ежедневная сводка показывает текущий результат; отдельный alert приходит при смене статуса проверки.

## Проверки и управление

От root:

```sh
rc-service serverbot status
/usr/bin/python3 /usr/local/lib/homelab/probe.py
cat /var/lib/homelab-health/host.json
tail -n 30 /var/log/homelab-updates.log
```

Запуск `updates.py` вручную может установить разрешённые обновления, это не команда просмотра. Журналы сборщика и обновлений ротируются, секреты в snapshot не записываются.

Для отключения автоприменения убрать исполняемый режим у `/etc/periodic/daily/homelab-updates`. Проверка станет предупреждать об устаревшем результате через 36 часов. Для полного отката мониторинга: убрать только добавленную строку `homelab/probe.py` из root crontab, вернуть `config.toml` и три Python-модуля из `/root/serverbot-monitoring-before-20261105`, перезапустить ServerBot. Отключение расписания не удаляет данные ботов.

## Перенос host probe на другой сервер

`deploy/host/probe.py` проверяет SSH VM по адресу из `HOMELAB_KALI_SSH_HOST`. Задайте этот адрес только в root-owned окружении cron или защищённом конфиге сервера; не коммитьте его в код. Если переменная не задана, проверка Kali SSH выдаёт предупреждение. Текущий рабочий host probe и расписание на сервере не менялись этой подготовкой.
