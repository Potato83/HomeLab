# 🥔 Potato Chat Bot

Telegram-бот для групп на aiogram 3. Экономика, магазин, займы и игры работают
поверх транзакционного SQLite-ledger: ставки резервируются заранее, а повторный
callback или рестарт процесса не может повторно начислить выигрыш.

## Структура

- `potato_bot/` — код бота; обработчики команд и бизнес-логика разделены по папкам.
- `tests/` — тесты проекта.
- В корне — Docker, настройки окружения и документация.

## Что умеет бот

- `/ping` и `/all` — упоминания участников, уже известных боту; `/pat` —
  погладить ответом на сообщение. Есть короткие реакции на слова «раф/гаф/гав»
  и «картошка».
- `/pidor` — ежедневный случайный выбор участника чата.
- `/dig` — добыча 1–10 🥔 с настраиваемым кулдауном.
- `/give` — атомарный перевод ответом на сообщение.
- `/top` — баланс и винрейт участников.
- `/flip`, `/roulette`, `/bj` — казино с целыми ставками и серверной проверкой.
- `/pvp`, `/rps` — персистентные вызовы со ставками в резерве.
- `/shop`, `/settitle`, `/removetitle`, `/sleep` — предметы, титулы и игровая
  модерация.
- `/zaim` — 50 🥔 сейчас, автоматический возврат 55 🥔 через 30 минут.
  При нехватке средств баланс становится отрицательным долгом. Следующий займ
  доступен через 60 минут после срока возврата и только после погашения долга;
  уведомление о возврате повторяется после сбоя отправки.
  Копка и входящие переводы могут постепенно погасить долг; ставки, покупки,
  исходящие переводы и `/sleep` не списывают больше доступного баланса.
- `/admin` в личном чате — сводка по чатам, последние действия владельца,
  настройки и сброс данных без резервной копии; `/add` ответом на сообщение —
  ручная корректировка баланса только владельцем.

## Быстрый запуск

Требуются Docker и Docker Compose.

```bash
git clone https://github.com/Potato83/potato_chat_bot.git
cd potato_chat_bot
cp .env.example .env
```

Укажите в `.env`:

```env
BOT_TOKEN=токен_от_BotFather
ADMIN_IDS=123456789,987654321
TLS_VERIFY=true
```

Все ID в `ADMIN_IDS` получают доступ к `/admin` и `/add`. Если `ADMIN_IDS`
пуст или отсутствует, используется прежняя настройка `MY_ID`.

Запуск:

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f potato_bot
```

Для новой версии используется отдельный volume `potato_bot_data_v2`; база
создаётся пустой, старая `bot_database.db` не переносится. Volume сохраняется
между пересборками и перезапусками контейнера. Формат БД прежнего бота не
поддерживается; для обновлений новой версии применяются миграции схемы. При
несовместимой БД бот завершится с ошибкой.
Контейнер работает без root и с read-only root filesystem. Healthcheck только
читает SQLite и проверяет версию схемы и нужные таблицы. При запуске бот
блокирует второй процесс, использующий тот же файл базы.

## VPN, proxy и TLS

Проверка сертификатов включена по умолчанию и применяется только к HTTP-сессии
Telegram:

```env
PROXY_URL=socks5://host:port
TLS_VERIFY=true
TLS_CA_FILE=/app/data/custom-ca.pem
```

Для локального VPN с подменным сертификатом лучше передать его CA через
`TLS_CA_FILE`. Если это невозможно, можно явно установить `TLS_VERIFY=false`;
глобальные настройки `aiohttp` при этом не меняются.

## Локальная разработка

```bash
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
python -m pytest -q
bandit -r . -x ./tests,./.git,./.venv,./venv
python -m potato_bot.main
```

Настройки:

| Переменная | По умолчанию | Назначение |
| --- | ---: | --- |
| `DATABASE_PATH` | `./bot_database.db` | Абсолютный или относительный путь БД |
| `MIN_BET` | `1` | Минимальная ставка |
| `MAX_BET` | `1000000` | Максимальная ставка |
| `MAX_BALANCE` | `9000000000000000` | Защитная граница целого баланса |
| `GAME_TTL_SECONDS` | `900` | Срок жизни незавершённой игры |

## Гарантии экономики

- все денежные изменения проходят через таблицу `operations`;
- `operation_key` уникален, поэтому retry не дублирует списание или выплату;
- `/sleep` хранит результат и абсолютный срок ограничения, поэтому повтор того
  же сообщения не продлевает сон повторно; незавершённые ограничения бот
  повторяет после перезапуска;
- transfer и игровые расчёты выполняются через `BEGIN IMMEDIATE`;
- ставки PvP/RPS/блэкджека вычитаются из доступного баланса до начала игры;
- просроченная незавершённая игра возвращает резерв;
- игры используют `secrets.SystemRandom`, дробные балансы запрещены;
- отрицательный баланс создаёт только разрешённое взыскание займа или действие
  владельца; тратить деньги из долга нельзя.

SQLite-конфигурация рассчитана на один контейнер бота с общей локальной БД. Для
нескольких реплик нужен общий PostgreSQL/Redis deployment, а не копии SQLite.

## CI/CD

Runtime-зависимости зафиксированы в `requirements.lock`, а инструменты разработки
отделены в `requirements-dev.txt`. Workflow запускает Bandit, тесты и сборку
production image на `main` и `dev`. После успешной проверки `main` сервер
переключается на проверенный commit и собирает образ через Docker Compose.
GitHub Actions зафиксированы полными commit SHA.

Для deploy нужны secrets:

- `HOST`, `USERNAME`, `SSH_KEY`, `PORT`, `WORK_DIR`.

На сервере в `WORK_DIR` должны находиться `docker-compose.yml` и production
`.env`. Каталог должен быть Git-клоном проекта с remote `origin`, доступным по
SSH для пользователя deploy.

## Исправление кнопок игр — 05.11.2026

ID игры может иметь вид `pvp:chat_id:message_id`. Двоеточия внутри ID являются частью ключа, поэтому обработчики отрезают только фиксированный префикс действия. В блэкджеке версия кнопки отделяется справа. Деление всей строки на фиксированное число частей ломало поиск игры и вызывало ложное «Игра уже завершена».

Сценарии обработчиков с настоящей временной SQLite-базой находятся в `tests/test_game_callbacks.py`. Повторные нажатия проверяются на отсутствие повторных выплат; чужой пользователь и чужое сообщение не получают доступ к игре. Старые действительно истёкшие кнопки останутся истёкшими — создайте новый вызов, если время прежнего закончилось.
