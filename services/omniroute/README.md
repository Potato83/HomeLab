# OmniRoute

LLM gateway на Alpine: Podman запускает закреплённый OCI-образ, nginx ограничивает доступ к API и панели. OpenCode использует совместимый с OpenAI API.

`compose.yaml` — справочный контейнерный манифест; текущий сервер управляет контейнером через OpenRC. Не считать этот файл автоматической установкой сервера. `.env.example` содержит названия секретов без значений. Данные провайдеров и OAuth хранятся только на сервере.

Сначала создайте отдельные секреты, настройте закрытый сетевой доступ и требование API-ключа, затем выполните личную авторизацию провайдера. Проверяйте ответы API и запрет административных маршрутов для обычных клиентов.

В репозитории намеренно нет рабочих адресов, ключей, cookie и персональных bootstrap-скриптов.

## Автообновление на Alpine

`omniroute.openrc` управляет уже созданным контейнером `omniroute`.
`omniroute_update.py` обновляет только этот контейнер. Проверяемый канал —
`docker.io/diegosouzapw/omniroute:latest`, новый контейнер создаётся по digest.
На сервере используются `/srv/omniroute/.env`, `/srv/omniroute/data` и
установленный `control.py` из ServerBot. Скрипт обновления устанавливается
рядом с `control.py` в `/usr/local/lib/homelab/`, с доступом только для root.
В серверном `.env` должны быть заданы bind `127.0.0.1`, порт 20127,
`REQUIRE_API_KEY=true` и используемые параметры прокси из `compose.yaml`.

Установите `nginx-maintenance.conf.example` в `http.d` как
`omniroute-maintenance.conf`. В оба серверных блока, проксирующих OmniRoute
(имя панели и порт 20128), добавьте временный ответ для клиентов.

```nginx
if (-f $omniroute_maintenance_file) {
    return 503;
}
```

В блоке 20128 добавьте `listen 127.0.0.1:20128;` и `allow 127.0.0.1;`
в location для `/v1`. Проверьте `nginx -t` перед reload. Локальный
`/v1/models` на 20128 должен отвечать HTTP 401 без ключа, локальный
`/api/monitoring/health` на 20127 — HTTP 200. Затем замените
`/etc/init.d/omniroute` шаблоном OpenRC из этого каталога.

Добавьте в существующий root crontab. Время соответствует часовому поясу
сервера. `--recover` завершает прерванную замену, в обычном состоянии он
завершается сразу.

```cron
30 4 * * * /usr/bin/python3 -B /usr/local/lib/homelab/omniroute_update.py 2>&1 | /usr/bin/logger -t omniroute-update
* * * * * /usr/bin/python3 -B /usr/local/lib/homelab/omniroute_update.py --recover 2>&1 | /usr/bin/logger -t omniroute-update
```

Обычный ручной запуск использует ту же команду, что ночное задание.
При одинаковом образе контейнер продолжает работать. Во время замены входы
nginx отдают 503, а локальные проверки остаются доступны. Если новый
контейнер не проходит проверку, скрипт возвращает предыдущий контейнер и
его данные, затем повторяет проверки. При прерывании тот же режим
`--recover` можно запустить вручную.

Для ручного возврата после уже завершившегося обновления используйте в паре
`localhost/homelab/omniroute:previous` и `/srv/omniroute/.update/previous`.
Сначала временно отключите ночное задание и убедитесь, что `pending.json`
отсутствует. Закройте клиентский трафик флагом обслуживания nginx,
остановите сервис через OpenRC и сохраните копию текущих данных и контейнера.
Восстановите содержимое предыдущего снимка с владельцем и правами, создайте
контейнер с тегом `:previous` и теми же флагами Podman из `create()`.
Запустите сервис с временным `/run/homelab-omniroute-start`. Удалите его
после старта. Удалите флаг обслуживания после проверок HTTP 200 и 401.
Снимок отражает состояние на момент предыдущей замены, поэтому изменения
после неё останутся в копии текущих данных.

Для регулярной проверки ServerBot использует `/healthz`, как штатный
healthcheck OmniRoute. Перед заменой и после неё обновлятор дополнительно
вызывает `/api/monitoring/health`, который проверяет SQLite.

В `/srv/omniroute/.update` хранится одна предыдущая согласованная копия.
Для предыдущего образа используется тег `localhost/homelab/omniroute:previous`.
Очистка касается временных файлов обновления, старых копий и ранее
использованных обновлятором образов без других тегов и контейнеров.
Обновлятор проверяет наличие 8 ГиБ свободного места на файловой системе
`/srv/omniroute` перед скачиванием и перед остановкой контейнера. Поддерживаемая
OmniRoute переменная `CALL_LOG_MIN_FREE_DISK_MB=8192` прекращает запись новых
артефактов запросов при малом остатке места. Она читается при создании
контейнера из `.env`.
